## Что это

«Стоматология для пациента» — информационный артефакт. Один HTML-файл. Работает офлайн. Не собирает данные.

Политика ниже описывает, что защищено, что не защищено, и как сообщить о проблеме.

---

## Приватность

**Персональные данные не обрабатываются.**

Артефакт работает полностью в браузере пользователя. Не отправляет данные на серверы. Не использует аккаунты. Не требует регистрации. Не ставит cookies. Не использует аналитику.

В соответствии с ФЗ-152 от 27.07.2006 «О персональных данных» артефакт **не является оператором персональных данных**, потому что персональные данные не собираются и не обрабатываются.

### Что хранится локально

В `localStorage` браузера хранятся только технические настройки:

| Ключ | Что | Зачем |
|:-----|:----|:------|
| `dental-patient.themeMode` | `dark` / `light` / `auto` | Помнит выбранную тему |
| `dental-patient.font` | `normal` / `large` / `xlarge` | Помнит размер шрифта |
| `dental-patient.read` | список ID прочитанных плиток | Прогресс чтения |
| `dental-patient.open` | список ID открытых плиток | Открытые разделы после перезагрузки |

Эти данные не покидают устройство. Их можно удалить в любой момент — кнопкой «Сбросить прогресс» в шапке артефакта или через настройки браузера.

## Сеть

**Ни одного сетевого запроса.**

CSP-заголовок артефакта:
default-src 'none';
style-src 'unsafe-inline';
script-src 'unsafe-inline';
worker-src 'self' blob:;
img-src data: blob:;
manifest-src 'self' blob:;
font-src 'none';
connect-src 'none';
base-uri 'none';

text

Ключевое: `connect-src 'none'`. Это запрет браузеру на любой сетевой запрос — fetch, XHR, WebSocket, sendBeacon, любой другой.

### Ограничение на `file://`

При открытии файла локально (через `file:///...`) браузеры **не применяют** CSP-заголовки. Это нормальное поведение браузеров, а не баг. При работе с хостинга (GitHub Pages и других) CSP применяется полностью.

Артефакт предупреждает об этом при открытии через `file://`.

## Код

**Безопасные практики:**

- **Без `eval()`.** Функции `eval()` и `new Function()` не используются.
- **Без `document.write()`.** Весь DOM строится через `createElement` и `innerHTML` с предварительным экранированием.
- **Без inline-обработчиков.** Все события через `addEventListener`, ни одного `onclick=`.
- **Без внешних ресурсов.** Ни CDN, ни шрифтов, ни картинок с чужих серверов. Всё внутри файла.
- **Без сторонних библиотек.** Ноль зависимостей.

### Service Worker

Регистрируется через `blob:` (не через отдельный файл). Кэширует только запросы того же origin. Ничего не отправляет наружу.

## Известные ограничения

1. **CSP не работает на `file://`.** Техническое ограничение браузеров, а не артефакта.

2. **localStorage ограничен по объёму.** Обычно 5–10 МБ, но мы храним менее 1 КБ.

3. **Service Worker требует HTTPS.** На `file://` не регистрируется. Это нормально — артефакт работает и без SW, просто без кэша после первого открытия.

4. **PWA-иконка генерируется через Canvas.** Если Canvas заблокирован в браузере, иконка не создастся, но артефакт продолжит работать.

5. **Schema.org-разметка может не индексироваться.** Некоторые поисковики игнорируют микроразметку. Это не влияет на работу артефакта.

## Обновления безопасности

Артефакт — статический HTML-файл. Обновления выпускаются, когда:

- Изменяются клинические рекомендации.
- Найдена ошибка в содержании.
- Обновляется CSP или стандарты безопасности.

Каждое обновление — новый тег вида `v1.0.1`, `v1.0.2`. Отпечаток файла фиксируется SHA-256 в описании релиза.
